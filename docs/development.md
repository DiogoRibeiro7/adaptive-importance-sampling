# Development

This page covers working on Safe-ICE itself. The contribution workflow, from
branch names to commit messages, is in
[CONTRIBUTING.md](https://github.com/DiogoRibeiro7/adaptive-importance-sampling/blob/main/CONTRIBUTING.md).

## Setting up

Development dependencies are declared as PEP 735 dependency groups in
`pyproject.toml`, so any recent installer can read them:

=== "pip"

    ```bash
    git clone https://github.com/DiogoRibeiro7/adaptive-importance-sampling.git
    cd adaptive-importance-sampling

    pip install -e .
    pip install --group dev          # pip >= 25.1
    pre-commit install
    ```

=== "uv"

    ```bash
    git clone https://github.com/DiogoRibeiro7/adaptive-importance-sampling.git
    cd adaptive-importance-sampling

    uv sync --group dev
    uv run pre-commit install
    ```

=== "Poetry"

    ```bash
    git clone https://github.com/DiogoRibeiro7/adaptive-importance-sampling.git
    cd adaptive-importance-sampling

    poetry install --with dev        # poetry >= 2.1
    poetry run pre-commit install
    ```

The groups are:

| Group | For |
| --- | --- |
| `dev` | Tests, linting, type checking, security scanning and pre-commit |
| `docs` | Building this site |
| `benchmark` | Running and regenerating the notebooks |

`poetry.lock` pins every group, so Poetry installs are reproducible.

## Everyday commands

| Task | Command |
| --- | --- |
| Fast tests | `pytest` |
| All tests, including slow ones | `pytest -m ""` |
| Lint | `ruff check .` |
| Format | `ruff format .` |
| Type check | `mypy` |
| Coverage | `pytest --cov=safe_ice --cov-report=html` |

`pytest` skips tests marked `slow` by default so the common case stays quick;
CI runs the full set. The other markers are `integration`, for end-to-end tests
across modules, and `benchmark`. Warnings are errors in the test suite, apart
from `UserWarning` and deprecation warnings.

Ruff handles both linting and formatting, and mypy runs in strict mode over the
package. The `Makefile` wraps the same commands (`make check` runs all of them).

## Documentation

This site is built with [MkDocs](https://www.mkdocs.org/) and
[Material for MkDocs](https://squidfunk.github.io/mkdocs-material/), and
published to GitHub Pages.

=== "pip"

    ```bash
    pip install --group docs
    mkdocs serve                     # live preview at http://127.0.0.1:8000
    mkdocs build --strict            # what CI runs
    ```

=== "Poetry"

    ```bash
    poetry install --only docs --no-root
    poetry run mkdocs serve
    poetry run mkdocs build --strict
    ```

- `mkdocs.yml` holds the configuration and navigation.
- `docs/` holds the pages. `docs/stylesheets/extra.css` styles the landing page,
  and `docs/javascripts/mathjax.js` configures equation rendering.
- The [API reference](api/index.md) is generated by
  [mkdocstrings](https://mkdocstrings.github.io/) from the docstrings in
  `safe_ice/`, read from the source tree rather than an installed copy.
- The [changelog](changelog.md) page includes `CHANGELOG.md` directly, so it is
  never edited in two places.

The build is strict: a broken link, a missing page, a heading anchor that no
longer exists or a docstring that does not parse fails it.

### Writing docstrings

Docstrings follow the NumPy convention and are rendered as Markdown, not
reStructuredText:

- inline code takes backticks, single or double;
- cross-references use mkdocstrings syntax, for example
  `` [`SafeICE`][safe_ice.SafeICE] ``, and must point at an object the API
  reference renders. Refer to private helpers as plain code;
- mathematics goes between `$...$` inline or `$$` on lines of their own;
- notes use admonitions such as `!!! note`, and code examples use fenced
  `` ```python `` blocks.

Run `mkdocs build --strict` after changing a docstring: an unresolved
cross-reference, or a parameter documented but missing from the signature,
fails the build.

## Notebooks

Each notebook in `notebooks/` is paired with a jupytext percent-format `.py`
file. Edit the `.py`, which reviews as an ordinary diff, then regenerate the
notebook with fresh outputs:

```bash
cd notebooks
jupytext --to ipynb --execute 01_getting_started.py
```

`scripts/check_notebooks.py` catches the two ways a committed notebook goes
stale:

```bash
python scripts/check_notebooks.py --sync      # does each .ipynb match its .py?
python scripts/check_notebooks.py --execute   # does each one still run?
```

## Continuous integration

| Workflow | Runs on | Checks |
| --- | --- | --- |
| **CI** | Pushes to `main`, pull requests | Ruff lint and format, strict mypy, the full test suite on Python 3.11 to 3.14 with coverage, a built and installed wheel, the documentation build, and bandit and pip-audit |
| **Documentation** | Pushes to `main` that touch the site's sources | Builds the site and deploys it to GitHub Pages |
| **Notebooks** | Changes to `notebooks/`, and weekly | That each notebook matches its `.py`; the weekly run re-executes every notebook |
| **Performance Regression Detector** | Pull requests | Benchmarks the branch against `main` on one runner and flags slowdowns above 15% |
| **Dependency Review** | Pushes and pull requests | New dependencies with known vulnerabilities |
| **Python Dependency Health Check** | Dependency changes, and weekly | Scores each direct dependency on maintenance and known vulnerabilities, and reports on the pull request or in a rolling issue |
| **Release** | `v*` tags | See [Release process](releases.md) |
| **Version bump** | Manual | Opens a pull request bumping the version |

A failed documentation build fails CI in the same way as a failed test.
